# 004. npm — 프로젝트가 쓰는 패키지를 설치하고 관리한다

> 정규 단계 03(설명). 설치·소스 변경·실행 검증은 하지 않았다. 아래 명령 예시는 모두 **아직 실행하지 않은 다음 단계 예시**다. 실제로 실행한 것은 npm 경로·버전 조회 두 개뿐이다.

## 1. 지금 해결할 문제

현재 프로젝트는 제목 한 줄을 보여 주는 [`index.html`](../../index.html) 하나뿐이다. 브라우저로 파일을 직접 열면 화면이 나온다([001](001-index-html.md)).

앞으로는 다음 도구와 라이브러리를 코드에서 사용해야 한다([진행 상태의 기술 구성](../progress.md#기술-구성--2026-09-25-선택)).

| 필요한 것 | 종류 | 쓰는 곳 |
| --- | --- | --- |
| Vite | 개발 서버·빌드 도구 | 개발할 때 내 컴퓨터에서 실행 |
| React, React DOM | 화면 라이브러리 | 이용자 브라우저에서 실행 |
| React Router | 라우팅 라이브러리 | 이용자 브라우저에서 실행 |
| @supabase/supabase-js | 원격 데이터 SDK | 이용자 브라우저에서 실행 |

이런 남이 만든 코드 묶음을 **패키지(package)** 라고 한다. 프로젝트가 동작하려면 반드시 있어야 하는 패키지를 그 프로젝트의 **의존성(dependency)** 이라고 부른다.

패키지를 쓰려면 네 가지 문제를 해결해야 한다.

1. **구하기**: 패키지 코드를 어디서 받아 오는가.
2. **버전 맞추기**: 어떤 버전을 쓸지, 그 패키지가 다시 필요로 하는 다른 패키지(하위 의존성)까지 서로 맞는 버전으로 모을 수 있는가.
3. **기록하기**: 무엇을 어떤 버전으로 쓰는지 남겨서, 다른 컴퓨터(배포 서버 포함)에서도 같은 구성을 만들 수 있는가.
4. **실행하기**: Vite 같은 개발 도구를 명령으로 실행할 수 있는가.

## 2. 기존 방식과 가능한 대안

| 방식 | 가능 여부 | 필요한 추가 작업·제약 | 이번에 선택하지 않은 이유 |
| --- | --- | --- | --- |
| 지금처럼 HTML 파일을 브라우저로 직접 열기 | 현재 화면에는 가능 | 패키지를 구하는 기능이 없다. Vite 같은 개발 도구는 브라우저가 아니라 Node.js에서 실행해야 한다([003](003-nodejs-role.md)). | 앞으로 필요한 개발 도구를 실행할 수 없다. |
| 패키지 파일을 직접 내려받아 폴더에 복사 | 기술적으로는 가능 | 하위 의존성까지 사람이 찾아 모으고, 버전·갱신 이력을 따로 적어야 한다. | 구하기·버전 맞추기·기록하기를 모두 손으로 해야 해서 실수가 생기고 다른 컴퓨터에서 같은 구성을 재현하기 어렵다. |
| `<script>`로 외부 주소(CDN)의 파일 연결 | 브라우저에서 실행되는 일부 라이브러리는 가능 | 개발 도구(Vite)는 이 방식으로 실행할 수 없다. 버전은 각 주소에 흩어져 기록된다. | 개발 도구 실행과 의존성 기록이 한곳에서 해결되지 않는다. |
| 다른 패키지 매니저(yarn, pnpm, bun, deno) | 가능 | 별도 설치·사용법 학습이 필요하다(도구마다 다름). Vite 공식 문서도 npm·yarn·pnpm·bun·deno 명령을 함께 안내한다. | 필수가 아니다. 선택하지 않은 이유는 아래 3절. |
| **npm** | 가능 | 이미 설치되어 있다(4절). | **선택** |

정리하면, "패키지 매니저 없이 수동으로 관리"는 불가능하지는 않지만 관리 부담이 크고, 개발 도구 실행까지 고려하면 **어떤 패키지 매니저든 하나는 쓰는 것**이 현실적이다. 그중 무엇을 쓸지는 선택 사항이다.

## 3. npm이 맡는 일과 선택 이유

npm 공식 문서는 npm이 세 부분으로 이루어진다고 설명한다([About npm](https://docs.npmjs.com/about-npm)).

- **레지스트리(registry)**: JavaScript 패키지와 그 정보를 모아 둔 대형 공개 데이터베이스. → "구하기"
- **CLI(명령줄 도구)**: 터미널에서 `npm ...` 명령으로 패키지를 설치·관리한다. 대부분의 개발자가 npm을 쓰는 방식이다. → "버전 맞추기·기록하기·실행하기"
- **웹사이트**: 패키지를 검색하고 계정·프로필을 관리한다.

같은 문서는 npm으로 할 수 있는 일로 앱에 패키지 코드를 가져와 쓰기, 코드와 의존성의 여러 버전 관리, 의존하는 코드가 갱신될 때 앱을 쉽게 갱신하기 등을 든다. 1절의 네 가지 문제를 한 도구로 해결한다.

**npm을 고른 이유**

- Node.js를 설치할 때 함께 설치되어, 현재 환경에 이미 있다(4절에서 확인). 추가 설치가 필요 없다.
- 프로젝트에서 이미 기술 구성으로 선택했고, Vite 공식 문서의 설치 예시에도 npm 명령이 포함된다([Vite 시작하기](https://vite.dev/guide/)).
- yarn·pnpm 등도 가능하지만, 이 과제에서 그 도구만의 기능이 필요한 근거가 없다. 새 도구를 하나 더 배우고 설치하는 비용만 늘어난다.

## 5. 설치 명령 `npm install`의 역할

npm v11 공식 문서([npm install](https://docs.npmjs.com/cli/v11/commands/npm-install)) 기준이다. `npm i`는 같은 명령의 짧은 별칭이다.

| 형태 (미실행 예시) | 하는 일 |
| --- | --- |
| `npm install <패키지>` | 레지스트리에서 패키지를 받아 **현재 프로젝트 폴더의 `node_modules`** 에 설치하고, 기본으로 프로젝트의 의존성 목록(`dependencies`)에 기록한다. |
| `npm install -D <패키지>` | 위와 같지만 개발할 때만 쓰는 의존성(`devDependencies`)으로 기록한다. Vite 공식 문서의 `npm install -D vite`가 이 형태다. |
| `npm install` (인자 없음) | 이미 기록된 의존성 목록을 보고 필요한 패키지를 `node_modules`에 한꺼번에 설치한다. 다른 컴퓨터에서 저장소를 받은 뒤 같은 구성을 만들 때 쓴다. |
| `npm install -g <패키지>` | 프로젝트가 아니라 컴퓨터 전역 위치에 설치한다. 이 프로젝트는 프로젝트 안에 의존성을 두므로 쓰지 않는다. |

설치 명령이 만들거나 바꾸는 파일은 세 가지다. 각 파일의 역할은 후속 단계에서 따로 다룬다.

- `package.json`: 프로젝트가 필요로 하는 패키지와 실행 명령의 기록 → 04 단계
- `package-lock.json`: 실제로 설치된 정확한 버전의 기록. 공식 문서는 잠금 파일의 버전이 `package.json` 범위를 만족하면 그 정확한 버전을 써서 같은 설치를 재현한다고 설명한다. → 05 단계
- `node_modules/`: 설치된 패키지 파일이 놓이는 폴더 → 06 단계

## 6. 전체 흐름에서 현재 위치와 향후 실행 순서

```text
01 React의 역할(완료) → 02 Node.js(완료) → [03 npm ← 지금] → 04 package.json
→ 05 package-lock.json → 06 node_modules → 07 Vite → 08 최소 패키지 환경 구성(첫 실제 npm 실행)
```

08 단계에서 예상되는 순서는 다음과 같다. **아직 실행하지 않았고**, 정확한 명령과 옵션은 04~07 단계 자료와 08 단계에서 확정한다.

1. `node --version`, `npm --version`으로 버전을 다시 확인한다.
2. 프로젝트의 `package.json`을 만든다. → `package.json` 생성
3. `npm install -D vite`처럼 개발 도구를 설치한다. → `package.json` 변경, `package-lock.json`·`node_modules/` 생성
4. `package.json`에 적은 실행 명령으로 Vite 개발 서버를 띄우고 기존 `index.html` 화면이 보이는지 확인한다.

React 등 브라우저에서 쓰는 라이브러리는 그 뒤 해당 단계(10 단계 이후)에서 같은 `npm install`로 추가한다.

## 7. 확인 결과와 남은 확인

- 실행 검증: 설명 단계이므로 해당 없음. npm 경로·버전 조회만 실제 수행했다(4절).
- 남은 확인: 실제 설치 동작과 생성 파일은 08 단계에서 확인한다.
