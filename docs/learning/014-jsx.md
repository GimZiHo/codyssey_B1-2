# 014. JSX — 화면 구조를 HTML과 비슷한 문법으로 적는다

> 단계: 정규 13단계(변경), 완료. 1~5절은 구현 전에 작성한 계획이고, 실제 변경·검증 결과는 [6절](#6-실제-결과)에 기록했다. 함수 컴포넌트·상태·라우팅·빌드·플러그인은 이번 단계에서 구현·검증하지 않았다.

## 1. 지금 해결할 문제

변경 전 화면의 제목은 [React 루트](011-react-root.md)에서 `createElement`로 만들었다.

```js
// src/main.js (변경 전 코드, 이번 단계에서 삭제)
root.render(createElement('h1', null, '학습 기록 서비스'));
```

요소가 하나일 때는 읽을 만하지만, 앞으로 목록·상세·폼 화면에서 태그가 겹겹이 중첩되면 `createElement(태그, 속성, 자식...)` 호출이 괄호 속 괄호로 늘어나 어떤 요소가 어느 부모 안에 있는지 파악하기 어렵다. 다음 단계(14단계, 함수 컴포넌트)부터는 컴포넌트가 화면 구조를 반환하게 되므로, 그 전에 화면 구조를 더 읽기 쉬운 문법으로 적는 방법을 준비한다.

## 2. 핵심 개념: JSX

- **JSX**: JavaScript 파일 안에서 HTML과 비슷한 마크업을 쓸 수 있게 하는 **JavaScript 문법 확장**이다. 브라우저는 JSX를 직접 실행하지 못하므로 실행 전에 일반 JavaScript로 **변환(transform)** 해야 한다.
- **변환 결과**: JSX 태그는 React 요소(화면 설명 객체)를 만드는 함수 호출로 바뀐다. React 공식 문서는 `createElement`를 "JSX를 쓰는 것의 대안"으로 소개하며 두 방식이 같은 결과를 만든다고 설명한다. 즉 JSX는 새 기능이 아니라 **같은 React 요소를 만드는 다른 표기법**이다.
- **JSX와 React는 별개**: 공식 문서는 "JSX와 React는 서로 다른 것이며 함께 쓰는 경우가 많을 뿐 따로 쓸 수 있다"고 설명한다. 따라서 JSX는 React 사용의 필수 조건이 아니다(3절 비교 참고).

### 작은 입력 → 결과

| 입력 (JSX) | 같은 의미의 createElement |
| --- | --- |
| `<h1>학습 기록 서비스</h1>` | `createElement('h1', null, '학습 기록 서비스')` |
| `<h1 className="title">제목</h1>` | `createElement('h1', { className: 'title' }, '제목')` |

둘 다 `type: 'h1'`, `props.children: '학습 기록 서비스'`인 React 요소를 만든다. `root.render()`는 이 요소를 받아 `#root` 안에 실제 `<h1>` DOM을 만든다.

### 이번에 필요한 JSX 규칙(공식 문서 기준)

1. **하나의 최상위 요소**: 여러 요소를 반환하려면 부모 태그나 Fragment(`<>...</>`)로 감싼다. 이번 변경은 `<h1>` 하나라서 해당 없음.
2. **모든 태그를 닫는다**: `<img>` → `<img />`, `<li>항목` → `<li>항목</li>`.
3. **속성은 camelCase**: `class`는 JavaScript 예약어이므로 `className`을 쓴다. `aria-*`, `data-*`는 하이픈을 유지한다.

중괄호 `{}`로 JavaScript 값을 넣는 방법은 값이 필요한 props 단계에서 다룬다. 이번 제목은 고정 문자열이다.

## 3. 기존 방식과 대안 비교

| 방식 | 가능 여부 | 필요한 추가 설정 | 제약 | 판단 |
| --- | --- | --- | --- | --- |
| A. `createElement` 유지 (`src/main.js`) | 가능 | 없음 | 중첩이 깊어질수록 읽기 어렵다 | 동작에는 문제없지만 이번 단계의 목적(JSX 도입)과 맞지 않아 선택하지 않음 |
| B. **`src/main.jsx`로 이름 변경 + JSX**, `index.html` 경로 수정 | 가능 | 없음. Vite가 `.jsx`를 기본 변환 | 파일 확장자가 `.jsx`여야 한다 | **선택** |
| C. `src/main.js` 그대로 두고 안에 JSX 작성 | Vite 기본 설정에서는 **불가** | 설정 파일에서 `oxc.include`/`exclude` 변경 필요 | Vite 기본 Oxc 변환 대상은 `ts`·`jsx`·`tsx`이며 `.js`는 제외된다([012](012-vite-config.md), [013](013-vite-plugin.md)에서 확인) | 설정 파일을 늘릴 이유가 없어 선택하지 않음 |
| D. `@vitejs/plugin-react` 추가 | 가능 | 패키지 설치 + 설정 파일 `plugins` 등록 | JSX 변환 자체에는 필요 없다. 추가 이점은 Fast Refresh | 이번 목적(JSX 표기)에 필요 없음. 필요가 입증될 때 별도 판단([013](013-vite-plugin.md)) |
| E. Babel 브라우저 변환(`<script type="text/babel">`) | 가능 | CDN 스크립트 | 브라우저에서 매번 변환, 배포용으로 부적합 | Vite가 이미 변환을 맡으므로 선택하지 않음 |
| F. `oxc.jsxInject`로 `import` 자동 삽입 | 가능 | 설정 파일 | 기본 automatic 런타임이 필요한 import를 이미 넣는다 | 해결할 문제가 없어 선택하지 않음 |

### 선택 이유

- 이번 단계의 목표는 **표기법 변경**이다. Vite 공식 문서는 `.jsx` 파일을 "out of the box"로 지원하며 변환은 Oxc Transformer가 맡는다고 설명한다. 따라서 확장자만 바꾸면 패키지·설정·플러그인 추가 없이 JSX를 쓸 수 있다.
- [013](013-vite-plugin.md)에서 Vite 8.3.1 구현을 확인한 결과 JSX 런타임을 따로 지정하지 않으면 Oxc 기본값 **automatic**이 쓰인다. automatic 런타임은 변환 결과에 `react/jsx-runtime`(개발 모드는 `react/jsx-dev-runtime`) import를 자동으로 넣으므로, 파일에 `import React from 'react'`나 `createElement` import를 둘 필요가 없다.
- 이 내용이 실제로 맞는지는 **구현 후 개발 서버가 돌려주는 변환된 모듈 응답**으로 확인한다(5절). 기본 변환이 실패하는 근거가 나올 때만 설정·플러그인을 검토한다. 실제로 기본 변환만으로 동작했다(6절).

## 4. 수행 순서 (구현 전 계획)

아래는 구현 전에 세운 계획이다. 실제 수행은 계획과 같았으며 결과는 6절에 있다.

1. `src/main.js`를 `src/main.jsx`로 옮긴다. 기존 `.js` 파일은 남기지 않는다(진입 파일이 둘이면 어느 쪽이 쓰이는지 혼동된다).
2. 파일 안의 `createElement` import와 호출을 JSX로 바꾼다.

   ```jsx
   // src/main.jsx (예정)
   import { createRoot } from 'react-dom/client';

   const root = createRoot(document.getElementById('root'));
   root.render(<h1>학습 기록 서비스</h1>);
   ```

3. `index.html`의 모듈 스크립트 경로를 `/src/main.js` → `/src/main.jsx`로 바꾼다.

   | 파일 | 변경 (예정) |
   | --- | --- |
   | `src/main.js` | 삭제 (`src/main.jsx`로 이동) |
   | `src/main.jsx` | 새 파일, JSX로 제목 렌더링 |
   | `index.html` | `<script type="module" src="/src/main.jsx">` |
   | `package.json`, `package-lock.json`, Vite 설정 | 변경 없음 |

4. `npm run dev`로 개발 서버를 띄우고 5절 항목을 검사한 뒤 서버를 종료한다.

## 5. 확인할 항목 (구현 전 계획)

기존 10단계 검증과 같은 기준으로 화면이 그대로 유지되는지 확인한다.

- HTML 응답 200, 스크립트 경로가 `/src/main.jsx`
- `/src/main.jsx` 응답 200, JavaScript MIME, 응답 본문에 JSX 태그가 남지 않고 `jsx-dev-runtime` import로 변환됨
- 문서 제목·`lang`·문자 인코딩 유지
- `#root` 안 `h1` 텍스트, 계산 스타일(글자 크기·굵기·표시 방식), 박스 크기
- 새로고침 후 같은 결과
- 콘솔 오류·페이지 오류·요청 실패 없음
- 개발 서버 종료

## 6. 실제 결과

### 실제 변경

| 파일 | 실제 변경 |
| --- | --- |
| `src/main.js` | 삭제 |
| `src/main.jsx` | 새 파일. `createRoot`는 유지하고 `createElement` import와 호출을 JSX로 바꿨다 |
| `index.html` | 모듈 스크립트 경로 한 줄만 `/src/main.js` → `/src/main.jsx` |
| `package.json`, `package-lock.json`, Vite 설정 파일, 플러그인 | 변경·추가 없음 |

```jsx
// src/main.jsx (실제 코드)
import { createRoot } from 'react-dom/client';

// React 루트: #root 안쪽 DOM을 React가 관리한다.
const root = createRoot(document.getElementById('root'));
// JSX: Vite(Oxc)가 .jsx를 React 요소 생성 호출로 변환한다. automatic 런타임이 import를 자동으로 넣는다.
root.render(<h1>학습 기록 서비스</h1>);
```

변경 전과 비교하면 `import { createElement } from 'react'` 줄이 사라졌다. 파일에는 `react` import가 없지만, 아래 검증처럼 변환 결과에 JSX 런타임 import가 자동으로 들어간다.

### 실행 흐름

1. 브라우저가 `index.html`을 받고 `<script type="module" src="/src/main.jsx">`를 요청한다.
2. Vite 개발 서버가 `.jsx` 파일을 기본 Oxc 변환으로 일반 JavaScript로 바꿔 응답한다. JSX 태그 `<h1>…</h1>`는 `react/jsx-dev-runtime`의 함수 호출로 바뀌고 그 import가 자동으로 추가된다.
3. 변환된 코드가 `createRoot`로 `#root`를 React 루트로 만들고, JSX가 만든 React 요소를 `root.render()`에 넘긴다.
4. React가 `#root` 안에 `<h1>학습 기록 서비스</h1>` DOM을 만든다. 결과 화면은 변경 전과 같다.

### 검증 결과

- **환경**: 2026-09-28, Node.js `v24.18.1`, `npm run dev` Vite 개발 서버(포트 5183), Playwright headless Chromium shell. 검증 스크립트와 결과 JSON은 버전 관리 밖 임시 경로에 두었다.
- **결과**: 7건 통과, 실패 0건.

| 검사 | 실제 결과 |
| --- | --- |
| HTTP | HTML 200, 스크립트 경로 `/src/main.jsx`. `/src/main.jsx` 200, `text/javascript`. 응답 본문에 JSX 태그가 남지 않았고 `react_jsx-dev-runtime.js` import가 들어 있으며 `createElement` import는 없다 |
| 메타데이터 | 제목 `학습 기록 서비스`, `lang="ko"`, `UTF-8`, viewport 유지 |
| 렌더링 | `#root` 자식 1개, `h1` 텍스트 `학습 기록 서비스`. 계산 스타일 `display: block`, `32px`, `700`, 보임·불투명도 1. 박스 1264×38 |
| 새로고침 | 첫 로드와 같은 텍스트·박스 |
| 오류 | 콘솔·페이지 오류, 요청 실패, 오류 응답 모두 0건 |
| 로컬 링크 | 25건 확인, 실패 0건 |
| 서버 종료 | 종료 후 포트가 닫힌 것을 확인 |

- **관찰**: 삭제한 `/src/main.js`를 직접 요청하면 404가 아니라 200 `text/html`이 돌아왔다. 없는 경로에 개발 서버가 HTML을 대신 응답한 것으로, JavaScript 모듈로 제공된 것은 아니다. 화면은 `index.html`이 가리키는 `/src/main.jsx`만 사용한다.
- 구현 중 HTTP 검사의 판정 정규식을 고쳐 해당 검사만 다시 실행했으며, 위 표는 수정 후의 최종 결과다.

### 미확인·다음 단계

- 수정 시 화면 부분 갱신(Fast Refresh)은 React 플러그인을 추가하지 않았으므로 확인 대상이 아니다([013](013-vite-plugin.md)).
- 프로덕션 빌드 결과의 변환(`react/jsx-runtime`)은 빌드를 구성하지 않아 확인하지 않았다.
- 다음 14단계(함수 컴포넌트)에서 이 JSX를 반환하는 컴포넌트로 옮긴다. 이번 단계에서는 구현하지 않았다.
