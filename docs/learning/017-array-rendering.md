# 017. 배열 렌더링 — 데이터 배열을 map으로 JSX 목록으로 바꾼다

- 단계: [진행 상태](../progress.md) 정규 단계 16 (변경)
- 새 핵심 개념: 배열 렌더링 (`Array.prototype.map`으로 데이터 배열을 JSX 요소 배열로 바꿔 표시)
- 이전 개념: [JSX](014-jsx.md), [함수 컴포넌트](015-function-component.md), [props](016-props.md)
- 작성 시점: 소스 변경 전에 계획으로 작성했고, 변경·검토·브라우저 검증 뒤 4~6절을 실제 결과로 보완했다.

## 1. 현재 문제

지금 홈 화면(`src/pages/HomePage.jsx`)은 제목 하나(`<PageTitle title="학습 기록 서비스" />`)만 표시한다. 이 서비스의 핵심 데이터는 **학습 기록 여러 개**다. 앞으로 Supabase에서 받아올 기록도 "객체 여러 개가 담긴 배열" 형태로 도착한다.

따라서 기록 개수가 정해져 있지 않은 배열을 받아 **항목마다 같은 모양의 화면 요소**를 만드는 방법이 필요하다. 이번 단계는 원격 조회 없이, 컴포넌트 파일 안에 적은 정적 예시 배열로 이 방법만 익힌다.

## 2. 핵심 개념

### 2.1 JSX의 `{}` 안에는 "값을 내는 표현식"만 넣을 수 있다

[JSX](014-jsx.md)의 중괄호 `{}` 안에는 JavaScript **표현식**(값이 되는 코드)만 들어간다. `for`, `if` 같은 **문(statement)**은 값이 아니므로 `{}` 안에 쓸 수 없다.

React는 `{}` 안의 값이 **배열**이면 그 원소들을 차례대로 화면에 그린다. 즉 "JSX 요소들의 배열"을 만들 수만 있으면 목록을 표시할 수 있다.

### 2.2 `map`은 배열의 각 원소를 바꿔 같은 길이의 새 배열을 반환한다

`Array.prototype.map(callback)`

| 항목 | 내용 |
| --- | --- |
| 인자 | 원소마다 호출할 함수 `callback(element, index, array)`. 이번 단계는 첫 번째 인자 `element`만 쓴다. |
| 반환값 | 각 호출의 반환값을 **같은 순서**로 모은 새 배열. 원래 배열은 바뀌지 않는다. |

작은 입력부터 결과까지:

```js
// 예시(설명용, 프로젝트 파일이 아님)
const names = ['JSX', 'props'];
const items = names.map((name) => <li>{name}</li>);
// items: [<li>JSX</li>, <li>props</li>]  ← JSX 요소 2개가 담긴 배열
```

`<ul>{items}</ul>`처럼 이 배열을 `{}`에 넣으면 React가 `li` 두 개를 순서대로 그린다. 원래 배열의 순서가 곧 화면 순서다.

### 2.3 화살표 함수의 반환 형태 주의

- `(name) => <li>{name}</li>` : `=>` 바로 뒤가 식이면 그 값이 **자동 반환**된다.
- `(name) => { return <li>{name}</li>; }` : `=>` 뒤가 `{`로 시작하면 함수 본문이므로 **`return`을 직접 써야** 한다. 빠뜨리면 `undefined`가 반환되어 아무것도 표시되지 않는다.

공식 문서도 이 함정을 따로 경고한다([React 목록 렌더링](https://react.dev/learn/rendering-lists)).

### 2.4 `key` 경고 — 이번 단계에서는 해결하지 않는다

공식 문서는 "`map()` 호출 안에서 바로 만드는 JSX 요소에는 항상 key가 필요하다"고 설명한다. key 없이 목록을 그리면 React 개발 모드가 콘솔에 **"Each child in a list should have a unique "key" prop."** 경고를 출력한다. 이 프로젝트(React 19.3.0 개발 모드)에서 실제로 나온 문구는 [5절](#5-확인-결과)에 기록했다.

key는 새 핵심 개념이므로 [진행 상태](../progress.md)의 **17단계**에서 다룬다. 이번 단계는:

- key를 지정하지 않는다.
- 경고를 숨기거나 억제하지 않는다. 검증에서도 이 경고를 "예상된 경고"로 분리해 기록하고, 그 밖의 오류가 없는지를 확인한다.
- 이 경고는 현재 목록이 **바뀌지 않는 정적 배열**이라 화면 표시 자체에는 영향이 없다. 항목이 추가·삭제·재정렬될 때 React가 항목을 올바르게 대응시키려면 key가 필요하며, 그 확인은 17단계 범위다.

## 3. 대안 비교와 선택

| 방식 | 가능 여부 | 필요한 추가 요소·제약 | 이번 선택 |
| --- | --- | --- | --- |
| JSX에 `<li>`를 개수만큼 직접 나열 | 가능 | 데이터와 화면 구조가 섞이고, 개수가 바뀔 때마다 JSX를 고쳐야 한다. 원격 데이터 배열에는 쓸 수 없다. | 선택하지 않음 |
| `for` 문으로 요소 배열을 채운 뒤 `{}`에 넣기 | 가능 | `for`는 문이라 `{}` 안에 직접 못 쓴다. `return` 앞에서 빈 배열·`push`를 따로 작성해야 한다. | 선택하지 않음 (같은 결과를 `map`이 식 하나로 낸다) |
| `forEach`를 `{}` 안에서 호출 | 불가능 | `forEach`의 반환값은 항상 `undefined`라 그릴 요소 배열이 생기지 않는다. | 해당 없음 |
| `map` 결과를 변수에 담은 뒤 `{}`에 넣기 | 가능 | 목록이 길거나 조건이 붙을 때 읽기 쉽다. | 선택하지 않음 (목록이 짧아 인라인으로 충분) |
| **JSX `{}` 안에서 바로 `map` 호출** | 가능 | 공식 문서의 기본 예시 형태. | **선택** |
| 항목을 별도 컴포넌트(예: 기록 항목)로 분리 | 가능 | 새 파일·props 전달이 늘어난다. 재사용 컴포넌트 정리는 51단계 범위다. | 선택하지 않음 |
| 필터링(`filter`) 추가 | 가능 | 표시 범위를 바꿀 요구가 아직 없다(상태와 함께 19단계 이후). | 선택하지 않음 |

### 여러 요소를 하나로 감싸는 방법

컴포넌트는 요소 **하나**를 반환해야 한다. 제목(`PageTitle`)과 목록(`ul`)을 함께 반환하려면 둘을 감싸야 한다.

- Fragment(`<>...</>`): DOM에 감싸는 요소를 남기지 않는다. 가능하지만 이번 단계에서 새 문법을 더하지 않도록 **선택하지 않는다**.
- **`<div>`로 감싸기**: 이미 쓰고 있는 일반 JSX 요소다. `#root` 안에 `div`가 하나 더 생긴다. **선택**.

### 예시 데이터를 두는 위치

- 컴포넌트 함수 **밖**(모듈 최상위)의 `const` 배열에 둔다. 값이 바뀌지 않는 정적 예시이므로 렌더링마다 다시 만들 필요가 없다.
- 필드는 [진행 상태](../progress.md)의 데이터 구성 초안 중 목록에 필요한 **제목·프로젝트**만 쓴다. 날짜·분류·본문과 식별자는 데이터 모델 단계(28단계)에서 확정한다.
- 원격 조회·state·이벤트는 사용하지 않는다(각각 35·19·18단계).

## 4. 이번 단계의 변경 (실제 적용)

- 수정 파일: `src/pages/HomePage.jsx` 하나.
- 변경하지 않은 것: `src/main.jsx`, `src/components/PageTitle.jsx`, `index.html`, 패키지·Vite 설정. 원격 조회·state·이벤트도 쓰지 않았다.

`src/pages/HomePage.jsx`의 핵심 코드:

```jsx
// 정적 예시 배열: 원격 조회 전까지 쓰는 학습 기록. 배열 순서가 곧 화면 순서다.
const records = [
  { title: 'JSX', project: 'B1-2' },
  { title: '함수 컴포넌트', project: 'B1-2' },
  { title: 'props', project: 'B1-2' },
];

export default function HomePage() {
  return (
    <div>
      <PageTitle title="학습 기록 서비스" />
      <ul>
        {records.map((record) => <li>{record.title} ({record.project})</li>)}
      </ul>
    </div>
  );
}
```

- `records`는 컴포넌트 함수 밖의 모듈 최상위 `const`다. 원소는 `title`·`project` 두 필드만 가진 객체 3개다.
- 기존 제목 `<PageTitle title="학습 기록 서비스" />`는 그대로 두고, `div`로 제목과 `ul`을 함께 감쌌다.
- `li`에 `key`를 주지 않았다(17단계 범위).

실행 흐름:

1. `main.jsx`가 `<HomePage />`를 렌더링한다.
2. React가 `HomePage`를 호출하면 `records.map(...)`이 원소 3개마다 콜백을 호출해 `li` 요소 3개가 담긴 새 배열을 반환한다. 예: 첫 원소 `{ title: 'JSX', project: 'B1-2' }` → `<li>JSX (B1-2)</li>`.
3. React는 `ul`의 자식으로 받은 이 배열을 원래 순서대로 DOM `li`로 그린다.
4. 배열 자식에 key가 없으므로 개발 모드 콘솔에 key 경고가 출력된다(17단계에서 해결).

## 5. 확인 결과

Vite 개발 서버를 띄우고 브라우저 자동화 스크립트로 6개 시나리오를 확인했다. 결과: **통과 6건, 실패 0건**.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 모듈 응답 | 개발 서버가 `HomePage.jsx`를 200으로 응답. 변환 결과에 `records.map` 호출이 남아 있고 `li`는 JSX 변환 함수 호출로 바뀌었으며(원문 `<li>` 없음) key 속성은 없음 |
| 예시 순서·내용 | `li` 3개의 텍스트가 `JSX (B1-2)` → `함수 컴포넌트 (B1-2)` → `props (B1-2)`로 배열 순서와 같음. `h1`은 `학습 기록 서비스` 그대로. DOM 구조는 `#root > div > h1 + ul` |
| 실제 표시 | 계산 스타일: `h1`은 `display: block`·32px·굵기 700·높이 38px, `ul`은 `block`·높이 57px, `li` 3개는 모두 `display: list-item`·`visibility: visible`·`opacity: 1`·목록 기호 `disc`·높이 각 19px. `li`의 세로 위치가 위에서 아래로 배열 순서대로 증가 |

| 새로고침 | 다시 불러온 뒤에도 같은 3개 목록. 두 번 로드하는 동안 key 경고는 합계 2건(로드마다 1건), 그 밖의 오류 0건 |
| 서버 종료 | 검증 후 개발 서버 종료, 이후 요청에 응답 없음 |

React 19.3.0 개발 모드에서 실제로 출력된 key 경고(콘솔 `error` 수준, 로드마다 1건):

```text
Each child in a list should have a unique "key" prop. ... See https://react.dev/link/warning-keys for more information.
Check the render method of `HomePage`.
```

- 경고가 어느 컴포넌트의 렌더링에서 생겼는지(`HomePage`)를 알려 준다. 목록 전체에 대해 한 번 출력되며, 항목 3개마다 따로 나오지 않았다.
- 경고를 숨기거나 억제하지 않았고, 화면 표시(위 순서·스타일 결과)에는 영향이 없었다.
