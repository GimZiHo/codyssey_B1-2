# 진행 상태와 요구사항 체크리스트

요구사항 출처는 [과제 분석](requirement-analysis.md)과 [과제 PDF](Requirement_B1-2.pdf)다. 분석 문서는 당시 해석 배경으로 보존하고, 현재 결정·구현 체크리스트는 이 문서에서 관리한다. 체크박스는 구현하고 검증한 뒤 완료로 표시한다.

## 현재 상태

- **완료**: 기존 과제 분석 확인, 운영 지침·학습자료 작성 기준·공통 도구 정보 이관. 서비스 주제를 학습 기록으로 결정하고 자료 범위를 B1-1·B1-2로 확정. 백엔드·개발 및 배포 도구 선택(아래 기술 구성 참고). Git 저장소 초기화. 단일 `index.html` 기본 화면 구현·브라우저 검증·학습자료 반영.
- **진행 중**: 없음.
- **다음 작업 단위**: 현재 화면에서 필요한 변화와 그에 필요한 도구의 필요성을 먼저 설명한 뒤 실제 작업 순서로 진행한다. Vite 설치를 확정된 다음 단계로 미리 정하지 않는다.
- **그 다음**: 각 작업 완료 후 해당 개념을 학습한 것으로 간주하고 다음 작업으로 진행한다. 실제 개발 순서에 필요한 도구·설정은 함께 다루되 관련 없는 기능까지 묶지 않는다.
- **미정**: 데이터 모델 세부 사항·자료 본문 표시 및 이전 방식·원격 데이터 접근 권한. Supabase·Vercel 계정 및 프로젝트 연결 상태는 아직 확인하지 않았다.
- **자료 반영 대기**: 없음. `docs/learning/README.md` 최신 자료는 001로 복귀 반영 완료.
- **Git**: main과 기존 커밋 이력은 유지한다. 환경 구성 변경은 삭제·복원 커밋으로 되돌린다. 기존 미추적 과제·지침 파일은 보존한다.
- **검증 범위**: 로컬 `index.html`을 브라우저로 직접 열어 탭 제목·언어·문자 인코딩·화면 제목 실제 표시·오류 없음의 5개 항목 통과, 실패 0건. 이전 React 환경 검증은 현재 구현의 근거로 사용하지 않는다.
- **마지막 갱신**: 2026-09-25

## 서비스 주제와 자료 범위

- **주제**: 학습 기록 서비스. 핵심 데이터는 학습 기록 하나이며 등록·조회·수정·삭제를 제공한다.
- **포트폴리오 범위**: B1-1과 B1-2의 모든 학습자료. 다른 프로젝트는 현재 범위에 포함하지 않는다.
- **기존 자료 위치**: `../codyssey_B1-1/docs/learning/`. 2026-09-25 파일 목록 기준 번호가 붙은 Markdown 학습자료 25개와 `README.md`, `GUIDE.md`가 있다. 본문은 이번 범위 결정에서 검토하지 않았다. 안내 문서의 서비스 내 배치 방식은 이전 단계에서 정한다.
- **B1-2 자료**: 앞으로 작성되는 이 프로젝트 학습자료도 같은 서비스에 포함한다.
- **데이터 구성 초안**: 제목·프로젝트(B1-1/B1-2)·학습 날짜·분류·본문. 프로젝트는 학습 기록의 구분 속성으로 두며 별도 프로젝트 CRUD로 범위를 넓히지 않는다.
- **화면 구성 초안**: 홈·학습 기록 목록·상세·등록·수정의 5개 라우트와 Not Found.
- **진행 순서**: 서비스 CRUD 구현·검증 후 기존 자료를 이전한다. 원본 파일은 보존한다. 이번 단계에서는 자료 복사·원격 등록·기능 구현을 수행하지 않았다.

## 기술 구성 — 2026-09-25 선택

기술 선택은 유지하되 일괄 환경 구성은 사용자 요청으로 되돌렸다. 현재는 제목 한 줄의 `index.html`만 있고 `package.json`을 포함한 Vite·npm은 아직 도입하지 않았다. 개념을 하나씩 학습할 때 필요한 파일과 도구만 도입한다. 계정 생성·원격 연동·배포는 수행하지 않았다.

| 역할 | 선택 | 선택 이유 |
| --- | --- | --- |
| UI·언어 | React 18 이상, JavaScript와 JSX | B1-1의 JavaScript 경험을 이어가며 컴포넌트·상태 학습에 집중한다. |
| 개발·빌드 | Vite, npm | React 템플릿으로 개발 서버와 배포 빌드를 구성한다. 아직 미도입. |
| 라우팅 | React Router의 Declarative 모드 | BrowserRouter·Routes·Route로 URL과 페이지의 관계를 명시하고 데이터 요청은 훅에서 학습한다. |
| 스타일 | 일반 CSS | 기존 CSS 경험을 재사용한다. |
| 원격 데이터 | Supabase, @supabase/supabase-js | 학습 기록 하나를 테이블의 행으로 관리하고 JavaScript에서 CRUD를 호출한다. |
| 배포 | Vercel | Vite 빌드 결과를 배포한다. 상세 URL 직접 접근·새로고침을 위한 SPA rewrite를 배포 단계에 구성한다. |
| 소스 관리 | Git, GitHub | 로컬에서 검토한 작업 단위로 커밋하고, 사용자 요청 시 푸시한다. |

- **소스 경로**: `src/pages`, `src/components`, `src/hooks`, `src/lib`, `src/styles`. 환경 구성 단계에 필요한 경로부터 만들고 역할에 따라 확장한다.
- **버전 관리**: 2026-09-25 실행 확인 결과 Node.js `v24.18.1`, npm `11.16.0`, Git `2.43.0`, Claude Code `2.1.270`. 현재 Node.js는 Vite 공식 문서의 요구 범위를 충족한다. 패키지의 정확한 버전은 설치 시 호환성을 확인하고 `package-lock.json`에 기록한다.
- **원격 연동 경계**: 브라우저에는 Supabase URL과 publishable key만 사용한다. secret/service_role 키는 넣지 않는다. 환경변수만으로 데이터 접근을 제한할 수 없으므로 실제 학습자료 이전 전 읽기·쓰기 정책과 RLS를 확정한다. 인증 채택 여부는 이 단계에서 변경하지 않는다.
- **확인 근거**: [Vite 시작하기](https://vite.dev/guide/), [React Router Declarative 설치](https://reactrouter.com/start/declarative/installation), [Supabase React 연동](https://supabase.com/docs/guides/getting-started/quickstarts/reactjs), [Supabase API 키](https://supabase.com/docs/guides/getting-started/api-keys), [Vercel의 Vite 배포](https://vercel.com/docs/frameworks/frontend/vite). 2026-09-25 공식 문서 확인. 실행·빌드·원격 CRUD 검증은 환경 구성 및 구현 단계에서 수행한다.

## 필수 구현·제출 체크리스트

체크박스는 PDF의 필수 요구사항만 담는다. 해석·예시·선택 사항에 대한 설명은 각 절의 `참고`로 따로 둔다.

### 프로젝트와 컴포넌트 — PDF 3쪽, 5~6쪽

- [ ] React 18 이상으로 구현한다.
- [ ] 서비스 주제는 직접 정하되 단일 핵심 데이터 CRUD가 가능한 수준으로 제한한다.
- [ ] pages, components, hooks 또는 lib의 역할을 분리한다.
- [ ] 주요 페이지에 공통 헤더·내비게이션 등의 레이아웃을 적용한다.
- [ ] 최소 8개의 재사용 컴포넌트를 구성한다.
- [ ] 재사용 컴포넌트는 최소 1개 이상의 prop을 받아 표시나 동작이 달라져야 한다.
- [ ] 페이지 컴포넌트와 UI 컴포넌트를 분리한다.
- [ ] 로딩·에러·빈 상태 UI는 재사용 컴포넌트로 통일한다.

### 라우팅 — PDF 2~3쪽

- [ ] 최소 5개 페이지 라우트가 동작해야 한다.
- [ ] 목록과 상세 라우트를 포함한다.
- [ ] 잘못된 주소에는 Not Found 페이지를 표시한다.
- [ ] 내비게이션으로 주요 라우트에 이동할 수 있어야 한다.

참고: PDF 2쪽의 라우트 예시(`/login` 포함)는 참고용 구성이며, 로그인 필수나 인증 구현을 요구하지 않는다. 인증은 5쪽의 보너스 과제다.

### 상태와 렌더링 — PDF 3~4쪽

- [ ] 폼 입력을 controlled input으로 관리한다.
- [ ] 목록·상세 데이터와 로딩·에러를 React 상태로 관리한다.
- [ ] 데이터 조회·갱신 흐름 중 최소 1개를 커스텀 훅으로 분리한다.
- [ ] 사용자 이벤트 → 상태 변경 → 렌더링 변화가 최소 3곳에서 명확히 드러나야 한다.
- [ ] 핵심 화면에서 로딩·에러·빈 상태를 일관되게 처리한다.

### 원격 CRUD와 폼 — PDF 4쪽

- [ ] Supabase 또는 Firebase 중 하나를 사용한다.
- [ ] 핵심 데이터의 등록·조회·수정·삭제가 반드시 원격 데이터 기준으로 동작해야 한다(브라우저 저장소만 사용하는 구현으로는 충족하지 못한다).
- [ ] 목록을 표시하고, 상세 화면은 라우트 파라미터로 특정 데이터를 조회한다.
- [ ] 등록·수정 성공 시 이동 또는 갱신하고, 삭제 후 목록 갱신 또는 이동한다.
- [ ] 등록·수정 폼에 필수값 검증과 오류 표시를 구현한다.
- [ ] 제출 중에는 버튼 비활성화 또는 스피너 등으로 진행 상태를 표시한다.
- [ ] 네트워크·권한 등의 요청 실패를 화면에 표시한다.

### 배포와 제출 — PDF 2쪽, 4~6쪽

- [ ] 외부에서 접속할 수 있는 URL과 GitHub 저장소 URL을 제출한다.
- [ ] 배포 환경에서 목록·상세 조회와 등록·수정·삭제가 모두 동작해야 한다.
- [ ] README에 로컬 설치·실행 명령어와 기술 스택을 명시한다.
- [ ] 민감 정보는 .env에 저장하고 .gitignore에 .env를 포함하며, 키가 포함된 코드를 GitHub에 푸시하지 않는다.
- [ ] 배포 환경의 환경변수도 별도로 설정한다.

참고: PDF 2쪽의 Vercel·Netlify는 배포 예시이며 특정 플랫폼을 필수로 지정하지 않는다.

## 선택 사항

필수 범위 완료 뒤 필요성과 학습 효과를 검토한다. 아래 항목은 아직 채택하지 않았다.

- Context 등 전역 상태
- useMemo/useCallback/React.memo 중 하나 이상의 메모이제이션
- Supabase/Firebase Auth와 보호 라우트
- TypeScript, 반응형 디자인

## 학습 진행 원칙

파일·명령별로 작업을 인위적으로 쪼개지 않고 실제 개발 순서에 따라 하나의 목적을 정해 진행한다. 학습은 사용자가 자율적으로 진행하며, 작업 완료 후 해당 목적의 내용을 학습한 것으로 간주한다. 이해 확인 질문·설명 요청·학습 완료 승인이나 별도 학습 확인 상태 기록 없이 다음 작업으로 진행한다.
